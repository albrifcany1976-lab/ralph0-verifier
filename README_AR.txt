رالف-0 — ملفات التحقق الفعلية — Implementation R1
التاريخ: 2026-10-29

هذه حزمة شيفرة قابلة للمراجعة والرفع، وليست مجرد مواصفة.
الحالة: اختبارات محلية للمشرف؛ لم تُشغّل على GitHub ولم يُثبت عزل Docker بعد.
لا تشغيل للإصلاح الفعلي ولا وصول إلى الإنتاج بهذه الحزمة.

ما تحتويه
- .github/workflows/verify.yml: إجراء يدوي على ubuntu-24.04، وصلاحية contents: read.
- verifier.py: مشرف خارج الحاوية؛ جلب النسخ وفحص كامل الفرق وإعادة التركيب والمهلة والأدلة.
- control/: مشغل اختبار SymPy ومجسا الكناري والمهلة، تركب للقراءة فقط.
- runtime/: وصف صورة مثبتة إلى index digest، وmpmath ببصمة، وتحقق شهادات أثناء التجهيز فقط.
- regression.patch وconfig.json: اختبار الانحدار المثبت والهوية والنتائج المتوقعة.
- reviewed_candidates.json: قائمة مراجعة المرشحين؛ فارغة عمدًا، فتمنع تشغيل أي إصلاح قبل مراجعته.
- tests/: اختبارات اصطناعية للمشرف، ونسخة نصية من اختبار الأساس لمطابقة النقل والتطبيق دون تنفيذه.
- seal.py وMANIFEST.json وSHA256SUMS: التحقق من بايتات الحزمة.

القرار الأحدث بشأن الوقت
توجيه المالك في المحادثة في 29 أكتوبر ألغى استعمال سقف الأربع/الست ساعات عائقًا للتقدم، وأعطى الأولوية لنتيجة محكمة ولو استغرق العمل يومين.
لذلك لا يوجد BLOCKED_BUDGET على أساس السقف القديم في هذا التنفيذ.
هذا لا يلغي مهلة كل عملية وحدود مواردها، ولا يبيح الإنفاق أو الوصول إلى الإنتاج.
ملفا القرارات والإجراء السابقان محفوظان كسجل تاريخي؛ هذا يوضح التغيير ولا يدعي تعديلهما.

مصدر اختبار الانحدار
regression.patch مشتق حرفيًا من hunks ملف الاختبار في PR الرسمي SymPy #21847، مع رؤوس diff القياسية وسطر نهاية.
ليست لدينا مطابقة بايتية لــ test_patch في نسخة SWE-bench المحملة؛ لا ندّعي تطابقها.
المصدر الرسمي يضيف أربعة تأكيدات، منها اثنان للمسار غير التبادلي.
نسخة اختبار الأساس مطابقة لــ Git blob 482cbee30dfd6716e97285ae4e766c25098c1eac.
التطبيق المحلي اختُبر دون استيراد SymPy أو تنفيذ اختبارات المشروع؛ بصمات الأساس والناتج في config.json.
لا تحتوي الحزمة إصلاح المصدر المرجعي؛ يتولى المنفّذ إنتاج مرشحه.

طريقة العمل على GitHub
1. ينشئ المالك مستودعًا عامًا فارغًا اسمه albrifcany1976-lab/ralph0-verifier، بفرع main.
   يجب أن تبقى صلاحيات منفّذ الإصلاح مقصورة على مستودع التجربة، عبر جميع التطبيقات والاعتمادات.
   المستودع العام قابل للقراءة؛ حماية التحقق هي منع الكتابة لا سرية الاختبار.
2. ترفع محتويات هذه الحزمة إلى جذر المستودع مع الحفاظ على .github/workflows/verify.yml؛ لا تُرفع كملف ZIP وحيد.
   إنشاء المستودع أو رفع الملفات لم يحصل هنا. لا يُضاف هذا المستودع إلى وصلة منفّذ الإصلاح.
3. تُراجع الملفات الفعلية، ثم يشغّل المشغّل المخوّل qualify بالأساس الافتراضي.
   مربعا boundary_confirmed وrun_authorized إقراران من المشغّل؛ لا يفحصان الصلاحيات تقنيًا بدلاً منه.
4. النتيجة المطلوبة للتأهيل: DRY_RUN_DETECTED_BUG، مع نجاح مجسات الحماية والإيقاف ورفض النطاق.
   هذا نجاح فحص الجهاز، وليس نجاح إصلاح. تفاصيل الفشل المتوقع يجب أن تكون في أثر التشغيل.
5. بعد تكليف المنفّذ والحصول على SHA مرشحه، يشغّل inspect لجمع الفرق دون استيراد المرشح.
6. يراجع مراجع مخوّل الفرق كاملاً. يضيف في reviewed_candidates.json سجلًا بالحقول:
   candidate: SHA الكامل؛ diff_sha256: بصمة الفرق من report.json؛ reviewer: هوية المراجع.
   ليس المطلوب نسخ البصمة فقط؛ السجل إقرار بمراجعة المنطق والنطاق ضد إسكات الاختبارات أو تزوير النتيجة.
   بعد تعديل هذا الملف تُعاد الأختام عبر python3 -B seal.py وتُلتزم الملفات معًا.
7. يشغّل verify على SHA نفسه؛ لا تغيير في المرشح بعد مراجعته. يعيد الإجراء المجسات ويختبر الأساس والناتج بالصورة المحلية نفسها.
8. يراجع المشغّل أثر التشغيل الكامل وحالته النهائية. نجاح تقني لا يدمج أو ينشر شيئًا.

اختبار محلي لمشرف التحقق فقط
python3 -B -m unittest discover -s tests -v
python3 -B seal.py --check
لا يشغّل الأمران أعلاه Docker أو SymPy أو اتصالًا بالشبكة؛ يستخدم الاختبار مستودع Git اصطناعيًا مؤقتًا.

السقوف المنفذة
الحاوية: 2 GiB ذاكرة دون Swap إضافي، حصّة CPU عدد 2، و128 عملية/خيطًا، و256 MiB لمساحة /tmp، و64 MiB للذاكرة المشتركة.
المخرجات: 2 MiB لكل تشغيل اختبار، و4 MiB لبناء الصورة.
الاختبار: 600 ثانية؛ مجس الكناري 15 ثانية؛ مجس المهلة 3 ثوانٍ.
جلب كل التزام: 180 ثانية؛ تصدير الأساس 90 ثانية وبحد 256 MiB؛ بناء الصورة 900 ثانية؛ job كاملة 45 دقيقة.
لا إعادة تلقائية. github.run_attempt يجب أن يساوي 1؛ هذا يمنع زر إعادة التشغيل، ولا يدّعي منع كل إرسال يدوي مكرر.
الجلب والبناء يعملان على العامل الزائل؛ ليس عليهما حد ذاكرة/قرص مخصص مثل حاوية المرشح. حدودهما تشمل مهلة العملية وحجم المخرجات وسعة العامل.
إذا انقطع عميل بناء Docker عند المهلة، يُعلن STOP_UNKNOWN_RUNTIME_BUILD؛ لا ندعي إثبات توقف أعمال daemon من قتل العميل.
إذا ألغي العامل أو قُتل المشرف قبل كتابة التقرير، لا نتيجة نجاح؛ يلغى التشغيل وتزال الآلة الزائلة بواسطة المنصة. لا يمكن ضمان كتابة سجل تنظيف بعد SIGKILL.

حدود الأمان والأدلة
حاوية المرشح بلا شبكة أو أسرار أو صلاحيات إضافية أو Docker socket؛ المراجع للقراءة فقط.
الإجراء لا يطبع مخرجات المرشح الخام إلى سجل أوامر Actions؛ يحفظها كملفات غير منفذة مع حدود حجم.
يلزم رفض تجاوز المهلة أو المخرجات أو OOM أو نقص النتائج، حتى مع رمز خروج صفر.
يجب أن يفشل الأساس في تأكيد السطر 116 بالسبب المتوقع، وتنجح اختبارات الملف الأحد عشر في الناتج.
هذا يمنع تغيير الملفات الخارجية؛ لا يثبت صدق Python عدائي يستطيع اصطناع مخرجات الاختبار. مراجعة المصدر شرط لهذا النطاق الصغير.
العزل والحماية من ثغرات النواة وتوافر GitHub وDocker ليست مثبتة محليًا.
الإجراء مكتوب ومفحوص محليًا؛ التأهيل الفعلي على عامل GitHub بوابة لازمة قبل استعماله للحكم.
المراجع الحالية تثبت أصل الحزم والبصمات؛ لا تعني تدقيقًا أمنيًا كاملًا لكل مكتبات الصورة التاريخية.
دعم Python 3.9 هنا لتجربة تاريخية محدودة بلا شبكة للمرشح، وليس اعتمادًا لبيئة إنتاج جديدة.

الشهادات والإنترنت
تحديث CA لعامل Ubuntu يسبق جلب المشروع، وGit يُوجّه صراحة إلى مخزن النظام مع التحقق مفعّلًا.
داخل الصورة يُحدّث CA في Debian ويُختبر رفض سلسلتي eMudhra مع اتصال إيجابي إلى PyPI.
مهلة الاتصال أو حظر الشبكة لا يُحسب نجاح رفض الشهادة.
PIP_CERT يوجّه تنزيل mpmath إلى مخزن النظام المصحح؛ الحزمة نفسها مثبتة ببصمة PyPI وتثبت من wheel فقط.
الصورة الأساسية مثبتة ببصمة index؛ apt قد يختار تحديثًا مصححًا أحدث. بعد البناء تسجل بصمة الصورة النهائية وحزمها ويستخدمها التشغيـلان محليًا دون سحب جديد.
إعادة التشغيل مستقبلًا ليست إعادة إنتاج بايتية مضمونة للصورة المبنية؛ يجب مقارنة بصماتها وأدلتها.
